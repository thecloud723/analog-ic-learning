## 0. 执行摘要

当前 PLL 已经形成比较完整的中文学习主线，课程组织和交互教学是主要优势；与 JKU、TI、ADI、Razavi 相比，仍不能说理论与工程设计深度全面超过这些资料。当前最主要的差距已经从“缺少章节”转向“真实实验和工程验证没有完全跟上”。

下一阶段不建议继续大量扩充理论章节，而应完成五件事：

1. **整理并冻结新版课程**：统一入口、目录、公式/图片来源、实验台账和验收口径。
2. **完成 Integer-N CP-PLL 完整闭环实验**：从逐边沿 PFD/分频反馈开始，连接 CP、Loop Filter 和 VCO，验证捕获、锁定、Cycle Slip 与非理想效应。
3. **完成可信的 Phase Noise / Jitter 实验**：建立分源噪声模型、闭环传递、积分抖动和 Spur 分离核算。
4. **补齐 Fractional-N 与 ADPLL 数字实验**：用定点模型/RTL 验证 MASH、Dither、TDC、DTC、数字 PI 和 DCO 校准。
5. **补充工程进阶验证**：PVT、器件非理想、电源耦合、板级问题、测量和调试。

建议按顺序推进。阶段 1 是后续工作的基线；阶段 2、3 是最重要的系统实验；阶段 4 是数字架构深化；阶段 5 是工程扩展。

- A：先认识整机，再理解反馈。

### 1.3 当前交互教学成熟度

当前交互适合分为四级，必须严格区分：

| Level | 定义 | 允许的表述 | 验收条件 |
|---|---|---|---|
| L1 | JS 公式、解析式或教学行为模型即时计算 | “教学模型”“理想模型”“行为模型” | 参数变化后即时更新；公式、单位、边界和简化假设清楚 |
| L2 | 由真实仿真/RTL/数值实验产生的预计算数据 | “SPICE 预仿真结果”“RTL 仿真结果”等 | 数据可追溯实验 ID、模型版本、参数、运行日志；未跑参数不能插值冒充真实仿真 |
| L3 | 作者已运行并保存的完整标准实验 | “作者已运行的实验工程” | 完整环境、源码/网表、参数、原始数据、日志、图表、运行版本和下载出口齐备；公开阅读已验证 |
| L4 | 读者复制后自行改参和重跑 | “可自行修改并运行” | 洁净账号/会话 Copy & Edit 验证；模型下载、依赖安装、运行、结果导出均通过 |

L3 和 L4 通常共用一份 Notebook：L3 是作者运行保存的基准版本，L4 是读者复制后的可修改版本。L1 和 L2 应留在网页，网页重点是快；L3/L4 负责完整实验。不是所有知识点都需要做到 L4。

当前较好的交互方向：

- A：时间差/相位差、频差累积、逐拍纠偏。
- B：LC 谐振、负阻起振、VCO 调谐、Bank/RO。
- C：PFD 时序、CP 电荷、滤波器零极点、Bode、瞬态和锁定。
- D：SSB 相噪、噪声传递、积分 Jitter、Spur 形成与读图。
- E：Fractional-N 序列、MASH、Dither、数字 PI、TDC/DTC。
- F：公开 EVM 和论文实测数据的读图、比较与验收。

交互验收不能只看“有滑块”。每个交互都要回答：用户改变了什么物理量、曲线哪个部分发生变化、背后的公式是什么、模型忽略了什么、真实电路中还会有什么额外因素。

## 阶段 2：完成 Integer-N CP-PLL 完整闭环实验

**优先级：最高。** 这是从“看懂 PLL”走向“能自己搭建和验证 PLL”的关键实验。目标不是简单把现有四个 Notebook 合并，而是建立一个物理边界清楚、可复现、能从初始频差运行到锁定的完整闭环。

### 2.1 先冻结系统规格和模型层次

建议首个基准配置沿用现有 PLL-SPICE 说明中的教学工况：

- 参考/PFD 频率：40 MHz。
- 目标输出：5 GHz。
- 整数分频比：N=125。
- 初始频差示例：-80 MHz。
- 环路滤波器、CP 电流、VCO 增益等参数必须以配置文件记录，不在代码中散落硬编码。
- 锁定判据：沿用或重新评估“频差进入 ±100 kHz 并连续保持 4 µs”的定义；同时记录相位误差和 VCTRL 条件，不能只靠单一频差判定。

必须明确区分三种模型，不要混成“全 SPICE”：

A. 事件驱动闭环行为模型：PFD、分频器、VCO 边沿、CP 脉冲按事件运行；Loop Filter 使用连续时间解析状态更新或数值积分。用于快速扫描和逐边沿机制教学。

B. SPICE 子电路模型：VCO 核心、CP、滤波器等可独立用 SKY130/ngspice 或现有仿真引擎运行；提取真实波形、KVCO、起振条件、输出摆幅、净电荷和非理想参数。

C. 混合级闭环模型：事件引擎与 SPICE 模型耦合。先采用稳定、可复现的分段耦合方式；若无法实时 co-sim，则明确使用经 SPICE 标定的模型参数，不得声称每个环路周期都由晶体管级 SPICE 直接求解。

首个可交付版本优先完成 A+B，并形成 C 的明确接口；随后再决定是否值得实现更高成本的紧耦合 co-simulation。

### 2.2 建立统一工程和参数配置

任务：

1. 将 PLL-01～04 的共同参数集中到 settings/config 文件。
2. 配置文件记录参考频率、目标频率、N、PFD、ICP、滤波器拓扑和元件值、VCO 中心频率、KVCO、VCO 控制范围、初始频偏、PFD reset delay、CP mismatch、仿真步长、停止条件。
3. 每个参数记录单位、来源类型：公开资料、SPICE 提取、手动假设、拟合值。
4. 每次运行生成唯一 run_id、配置快照、源码 commit、模型版本、运行时间、日志和输出目录。
5. 原始数据、降采样网页数据和图片分开保存；L2 导出必须能追溯回 L3 原始结果。
6. 保留现有 VCO-01、PLL-01～04 的工程，不重复实现已经可用的网表和数据导出器。

交付物：

- 统一 settings 文件。
- 实验目录规范。
- run manifest 和日志格式。
- 基准配置及其来源说明。

### 2.3 实现逐边沿 PFD 和整数分频反馈

任务：

1. 实现 REF 和 FB 两个边沿事件队列。
2. 建立双 DFF PFD 状态机：UP、DN、RESET 的置位/复位关系。
3. 加入 reset propagation delay，防止理想零延迟导致不真实行为。
4. 支持频率不等时的持续 UP/DN 输出，验证 PFD 能区分频差方向，而不只是静态相位差。
5. 实现 ÷N 计数器，N=125 为默认值，允许改 N。
6. 明确分频器输出边沿相对 VCO 边沿的延迟。
7. 验证 phase lead/lag、frequency lead/lag、相位误差跨周期回绕和初始状态。
8. 生成 REF、VCO、FB、UP、DN、RESET 的事件时间戳和波形。

交付物：

- PFD/Divider 事件模型。
- 可视化时序图。
- 至少 5 组测试：同频零相位差、正相位差、负相位差、REF 频率较高、FB 频率较高。
- PFD reset delay 和最小脉宽测试。

验收：

- UP/DN 方向正确。
- 频差不为零时能持续纠偏。
- N 分频边沿计数无 off-by-one。
- 事件序列可重复，日志可追溯。
- PFD 模型与独立 RTL/测试平台或手算事件结果一致。

### 2.4 连接 CP 和 Loop Filter

任务：

1. CP 按 UP/DN 脉宽输出电流脉冲，记录正负电荷。
2. 支持理想匹配、静态电流失配、UP/DN 延迟不匹配、有限输出电阻等分层模型。
3. 从现有 CP Ripple 数据和 PLL-02 净电荷实验复用参数，不复制另一套互不一致的 CP 模型。
4. Loop Filter 先实现与实际拓扑一致的连续时间状态模型；至少覆盖现有设计中的 R/C、零点和额外极点。
5. 用 SPICE 独立验证滤波器对单个 CP 脉冲的 VCTRL 响应。
6. 检查电荷守恒：积分电流得到净电荷，再与电容电压变化对应。
7. 记录 VCTRL 纹波、平均值、峰峰值和稳态偏移。
8. 将 UP/DN、ICP、VCTRL、滤波器内部状态画在同一时间轴。

交付物：

- CP 模型及参数说明。
- Loop Filter 状态更新模型。
- 单脉冲 SPICE 对照结果。
- CP mismatch / pulse mismatch 参数扫描。

验收：

- ΔQ、ΔV 和电流积分关系正确。
- 理想 CP 在对称条件下净电荷符合预期。
- 失配变化能产生方向合理的 VCTRL 纹波和静态偏移。
- 事件模型与独立 SPICE 脉冲响应在声明的误差范围内一致。

### 2.5 连接 VCO 并完成闭环

任务：

1. 首先使用线性 VCO：f_out=f0+KVCO·(VCTRL−V0)，并明确单位是 Hz/V 或 MHz/V。
2. 再接入 VCO-01/PLL-01 的 SPICE 调谐数据，使用查表或分段拟合得到非线性调谐曲线。
3. 限制 VCTRL 范围，超出范围时报告饱和/失锁，不允许无限线性外推。
4. 用相位累加器生成 VCO 边沿；边沿时刻由相位跨越 2π 决定，不能只用固定频率采样代替。
5. 将 VCO 边沿送入 ÷N，再回到 PFD，形成完整闭环。
6. 从 -80 MHz 初始频差启动，观察捕获过程、UP/DN、VCTRL、VCO 频率、FB 频率和相位误差。
7. 比较线性 VCO 与 SPICE 标定 VCO。
8. 加入 CP mismatch、reset delay、滤波器额外极点和 VCO 非线性，观察锁定时间和稳定性变化。
9. 识别 cycle slip，区分频率已接近但相位尚未稳定、真正进入锁定判据、以及 VCTRL 饱和。
10. 把 PLL-03 的平均相位域结果作为独立交叉校验，而不是删除现有模型。

交付物：

- LOOP-01 完整闭环工程。
- 默认基准运行全套波形和 CSV。
- 线性 VCO vs SPICE 标定 VCO 对比。
- 理想 CP vs 非理想 CP 对比。
- 捕获、锁定、失锁、Cycle Slip 案例。
- L2 网页数据导出。

验收：

- 从初始频差运行到锁定，且锁定判据可复现。
- 改变 N、ICP、R/C、KVCO、初始频偏后结果有合理变化。
- 与 PLL-03 平均相位域模型在小信号/稳态范围内交叉验证。

## 阶段 3：完成可信的 Phase Noise / Jitter 实验

**目标：** 从“能看懂相噪图”推进到“知道每个噪声源如何经过闭环影响输出，并能正确计算 RMS Jitter”。本阶段必须严格区分随机噪声和离散 Spur。

### 3.1 统一相噪、PSD、相位噪声和时间抖动定义

任务：

1. 明确 SSB Phase Noise L(f) 的单位 dBc/Hz、线性值和频偏定义。
2. 明确相位 PSD 的单边/双边定义，以及从 SSB L(f) 转换到相位方差时的系数。
3. 统一积分公式和约定：在小相位噪声近似下，若 L(f) 采用常见 SSB 线性定义，则相位方差通常由 2∫L(f)df 得到；每个页面必须注明定义和单双边约定，不能只贴公式。
4. 时间抖动转换：σt=σφ/(2πf0)，注明载波频率和积分带宽。
5. 说明积分上下限、测量带宽、仪器噪声底和是否排除离散 Spur。
6. 区分 period jitter、cycle-to-cycle jitter、TIE 和 integrated phase jitter；不能把所有 RMS 数字都叫同一种 Jitter。
7. 说明随机噪声谱密度与离散谱线不是同一物理量。

交付物：

- 统一噪声/Jitter 公式说明。
- 单位、单双边谱和积分口径检查表。
- 可复核的计算例题。

验收：

- 页面、Notebook 和测试脚本使用一致定义。
- 至少用一组可解析的简单噪声谱做数值积分对照。
- 改变积分上下限后，结果按预期变化。
- 不把 dBc、dBc/Hz、dB 和线性 PSD 混用。

### 3.2 建立噪声源模型库

至少分为：

- Reference source phase noise。
- VCO intrinsic phase noise。
- CP current noise / pulse noise。
- Divider / PFD noise。
- Loop Filter resistor thermal noise。
- 电源噪声通过 VCO pushing、CP coupling 等路径进入输出的噪声。
- 可选的 buffer/output stage additive noise。

每一项都记录：

1. 输入位置。
2. 噪声类型和单位。
3. 频率相关模型或导入数据。
4. 模型来源：公开曲线、器件仿真、测量、假设。
5. 是否已经包含在其他模块模型中，防止重复计算。
6. 适用频段和限制。

不要为了凑齐噪声源而凭空生成“真实器件噪声”。没有可信数据时，提供参数化教学模型，并明确标注假设。

### 3.3 建立闭环噪声传递和分源预算

任务：

1. 从线性化 PLL 模型推导 Reference、VCO、Divider、CP/Filter 等噪声到输出的传递函数。
2. 画出各噪声源的 transfer function，标明低频/高频抑制和放大区域。
3. 对每个噪声源分别计算输出 PSD，再在线性功率谱域相加，最后转成 dBc/Hz；不能直接在 dB 域相加。
4. 叠加总噪声曲线，并提供单项开关。
5. 改变 loop bandwidth、N、ICP、滤波器参数，观察噪声交叉点和总相噪变化。
6. 对照 TI/ADI 公开设计或 EVM 曲线，记录载波、参考频率、环路带宽、积分区间、仪器条件。
7. 将公开实测曲线与模型曲线分开显示，标明拟合数据点和留出验证点。

交付物：

- NOISE-01 分源噪声预算 Notebook。
- 各噪声源独立曲线和总曲线。
- 参数敏感度扫描。
- 至少一个公开器件/EVM 对照案例。

验收：

- 线性 PSD 相加正确。
- 各传递函数方向正确。
- 与解析极限/简单模型一致。
- 实测曲线对照保留测试条件和数据来源。
- 没有将假设噪声模型标成晶体管级 PNoise 或芯片实测。

### 3.4 Jitter 和 Spur 分开处理

任务：

1. 对随机相噪按指定积分区间计算 RMS phase jitter 和 RMS time jitter。
2. 让用户选择积分起止频偏，实时显示积分结果。
3. 对离散 Spur 单独列出频率和 dBc 幅度。
4. 若规格要求将 Spur 纳入总 jitter，必须说明采用的时域重建/积分规则，不得把单条 dBc 谱线直接当作连续 dBc/Hz PSD 积分。
5. 比较“排除 Spur”和“纳入指定确定性干扰”的结果。
6. 对 12 kHz–20 MHz 等典型规格区间，明确其来源，不要把某仪器截图的 1 kHz–40 MHz 结果直接当成同一规格。

交付物：

- Jitter 计算器和频谱交互。
- 随机噪声/离散 Spur 分离报告。
- 一组可复核的积分结果和边界说明。

### 3.5 仿真/测量验证层次

优先级：

A. 可解析噪声模型和数值积分：必须完成，用于验证公式和传递函数。

B. 由时域随机源产生噪声的行为/混合级实验：检查有限长度、窗函数、FFT、统计方差和积分结果的一致性。

C. 若所选开源引擎和模型支持，再评估真正的周期稳态噪声分析或等效 PNoise 工具链。没有 PSS/PNoise 能力时，不能用 transient FFT 冒充 PNoise。

D. 引入公开 EVM/论文测量曲线做对照，明确曲线是仪器实测、论文图像数字化还是模型生成。

验收：

- 理论积分、数值积分、时域统计三者在适用条件下相互吻合。
- 改变采样时间、记录长度、窗函数后，频谱误差有量化说明。
- 随机噪声与确定性 Spur 的计算路径分开。
- 所有结果带模型、工况、频带和数据来源。

## 阶段 4：补齐 Fractional-N 与 ADPLL 数字实验

**目标：** 从目前以公式和浮点行为模型为主的交互，推进到有限字长、可运行 RTL/定点模型和闭环验证。数字算法必须能够追溯到实际寄存器位宽、pipeline latency、复位和量化行为。

### 4.1 Fractional-N 与 MASH 1-1-1

任务：

1. 建立 Fractional-N 频率规划：N+α、NUM/DEN、fPFD、频率步进、序列周期。
2. 实现一阶累加器，逐拍显示状态、进位和瞬时分频命令。
3. 实现 MASH 1-1-1 三级累加器和误差抵消逻辑。
4. 对齐各级 pipeline latency，明确量化误差符号约定。
5. 实现有限字长、模回绕、饱和/截断和输出编码。
6. 增加 Dither seed、幅度、启停和复位控制。
7. 比较一阶、MASH 1-1、MASH 1-1-1 的输出序列、平均分频比和频谱。
8. 检查 idle tone、limit cycle、spur、噪声整形。
9. 将分频序列接入阶段 2 的 Integer-N PLL，形成 Fractional-N 闭环。
10. 比较理想平均分频模型和逐拍分频序列对输出相位、Spur 和锁定的影响。

交付物：

- DSM/MASH Python 或 JS 参考模型。
- 对应 RTL（优先 SystemVerilog）和 testbench。
- 定点位宽、延迟、复位和 seed 说明。
- 一阶/MASH/Dither 的频谱对比。
- Fractional-N 闭环实验 Notebook。

验收：

- 平均分频比与目标 α 一致。
- RTL 与参考模型逐拍一致。
- 各级延迟和误差抵消关系有自动测试。
- 频谱标注清楚：归一化 FFT、dBc 或 dBc/Hz 的适用条件，不能混称。
- 改 NUM/DEN、位宽、seed、Dither 后结果可复现。

### 4.2 ADPLL 数字闭环

任务：

1. 建立 FCW 目标相位轨迹。
2. 建立 DCO 实际相位和整数边沿计数。
3. 实现 TDC 亚周期时间量化，支持分辨率、量化噪声、DNL/INL 的参数模型。
4. 实现数字 PI：比例路径和积分状态分别可观察。
5. 实现 DCO 粗调/细调、频率增益、码字范围和饱和。
6. 记录误差、P 路径、I 状态、控制字、DCO 频率、相位误差。
7. 支持定点系数、内部位宽、舍入/截断、溢出和 pipeline latency。
8. 将 DTC 作为可选路径加入：解释其用途、预测相位误差、补偿码和 DTC 非线性。
9. 加入 DCO 增益两点校准或线性拟合校准，比较校准前后频率误差。
10. 加入 PVT 下 KDCO 变化、TDC/DTC 增益变化，观察闭环鲁棒性。
11. 对照真实 ADPLL 架构资料，注明不同实现可能采用不同的相位测量/校正路径，不把 TDC/DTC 写成所有 ADPLL 必备模块。

交付物：

- ADPLL-01 浮点参考模型。
- ADPLL-RTL 定点/RTL 模型和 testbench。
- TDC/DTC/DCO 参数模型。
- DCO 校准实验。
- 与现有 E3/E4 页面关联的交互和实验入口。

验收：

- 浮点与定点模型的误差有量化。
- 复位、位宽、溢出、延迟和码字边界有测试。
- 积分器状态在锁定后保留长期频率修正的物理含义解释正确。
- DCO 增益变化、TDC 量化和 DTC 非线性会产生合理且可解释的结果。
- 不把简化行为模型标成某一真实芯片的定点实现。

## 阶段 5：工程进阶验证

**目标：** 把教程从原理和理想模型延伸到真实设计中必须处理的 PVT、器件非理想、电源、PCB、测量和调试。此阶段不追求一开始做完整芯片，而是建立一组可复用、可解释的工程案例。

### 5.1 CP 晶体管级非理想

任务：

1. 使用公开 PDK（优先继续评估 SKY130）建立 UP/DN 电流源和开关结构。
2. 提取不同 VCTRL 下的 UP/DN 电流，测量 mismatch。
3. 分析输出电阻、compliance、开关注入、clock feedthrough、dead zone 和脉冲宽度不匹配。
4. 扫描供电、温度、器件尺寸和偏置。
5. 将晶体管级 CP 的 I-V、净电荷和纹波数据接回阶段 2 闭环模型。
6. 对照理想 CP、参数化 CP 和晶体管级 CP 三种结果。

交付物：

- CP transistor-level schematic/netlist。
- 电流匹配曲线、输出电阻、脉冲响应和 PVT 数据。
- 可导入闭环模型的 CP 参数表。

验收：

- 仿真网表和模型来源可追溯。
- 电流、失配和 VCTRL 依赖有明确数据。
- 参数化模型与 SPICE 提取结果在规定工作区间内吻合。

### 5.2 VCO/DCO PVT 和非线性

任务：

1. 在已有 VCO-01 基础上扩展工艺角、温度、电源电压。
2. 先确认模型卡、仿真引擎和温度参数确实生效，再运行扫描。
3. 扫描 L/C/Rs、MOS W/L、偏置、负载和电源。
4. 提取起振条件、频率、振幅、功耗、调谐范围、KVCO 和频率非线性。
5. 分析电容 Bank 的单调性、步进、DNL/INL 和粗细调交接。
6. 研究不同工作点 KVCO 变化对环路带宽和稳定性的影响。
7. 对 RO/DCO 增加延迟、增益和 PVT 模型，避免把 LC VCO 结果直接套给 RO。

交付物：

- VCO/DCO PVT 扫描表和曲线。
- KVCO/Bank 非线性模型。
- 对闭环稳定性和噪声预算的影响报告。

验收：

- 每个 corner 的模型、温度、电压真实生效。
- 结果可复跑。
- 说明哪些数据是 SPICE 结果、哪些是拟合模型。

### 5.3 电源噪声和耦合

任务：

1. 建立供电 ripple、随机噪声和周期性干扰输入。
2. 测量或仿真 VCO pushing、CP 电流变化和控制节点耦合。
3. 分别分析低频供电扰动、开关电源纹波和高频数字噪声。
4. 将供电扰动映射到频率调制、相位噪声和离散 Spur。
5. 比较理想电源、加入 3% 随机噪声、加入周期纹波、加入滤波/隔离后的结果。
6. 对每项结果说明扰动幅度、频谱、注入节点和传递路径。

交付物：

- 电源噪声注入实验。
- VCO pushing/CP sensitivity 数据。
- Spur 和相噪变化对比。
- 供电滤波/隔离建议。

验收：

- 注入源和单位明确。
- 不把随机噪声与周期纹波混为一谈。
- 能从输入扰动追踪到输出频谱变化。

### 5.4 PCB、参考源和板级调试

任务：

1. 建立参考时钟、PLL、VCO、输出缓冲、电源和地回路的系统框图。
2. 讲清参考源相噪如何传递、参考杂散如何形成。
3. 结合公开 EVM 资料，分析环路滤波器布局、敏感节点、地回流、供电去耦、屏蔽和串扰。
4. 建立常见故障案例：无法锁定、锁定时间过长、参考 Spur 偏大、相噪底抬高、输出功率异常、频率跳变。
5. 每个案例按“现象 → 可能原因 → 测量节点 → 验证方法 → 修复方案”组织。
6. 区分芯片内部问题、板级问题、仪器设置问题和配置错误。

交付物：

- EVM/PCB 调试专题。
- 故障树和测量检查表。
- 至少 3 个带数据/曲线的案例。

验收：

- 每个故障案例都有可操作的测量步骤。
- 结论有资料或数据支持，不只列经验性建议。
- 测量设置、探头、RBW/VBW、积分区间等条件明确。

### 5.5 实际测试和系统验收

任务：

1. 选取公开可追溯的 EVM 或论文测量数据作为基准。
2. 统一频率、参考源、分频比、环路带宽、输出路径、仪器和积分条件。
3. 分别记录规格值、设计参数、仿真结果和实测结果。
4. 对相噪、Jitter、Spur、锁定时间、频率范围和功耗建立验收表。
5. 记录模型与实测的偏差，解释哪些来自模型简化、未建模噪声或测试条件。
6. 形成从规格到设计、仿真、测量和结论的完整工程报告。

交付物：

- SYS-01 系统验收案例。
- 规格/设计/仿真/实测对照表。
- 测量条件和数据来源。
- 最终工程案例报告。

验收：

- 所有指标有定义、单位、条件和来源。
- 不把不同测试条件的曲线直接比较。
- 模型偏差和未覆盖因素明确。
- 报告可由第三方按记录复核。

## 6. 当前基线的主要风险和禁止误标事项

1. 新版 A–F 与旧版 01–18 章的文档口径尚未完全统一。
2. 旧版公式来源统计不能直接证明新版每页公式都已引用。
3. 图片已经下载/归档不代表新版页面已经全部使用原图替换。
4. JS 中使用 DFT、随机数或数值积分，不自动构成真实仿真 L2。
5. VCO-01 的 CI 复跑通过不代表 Kaggle 读者 L4 已通过。
6. PLL-03 的平均相位域闭环不等于 PFD/分频器逐边沿闭环。
7. PLL-04 的显式锁定脉冲和示例噪声预算不等于完整晶体管级 PLL 或实测相噪。
8. 0.197 ps RMS 只能按当前假设噪声谱和积分条件描述，不能写成芯片指标。
9. 只有在真实模型、运行日志和参数都可追溯时，才能标为 L2/L3。
10. 任何对外发布还需要单独检查 PDK、模型、图片、论文和软件依赖许可。

**最终目标：** 形成一套“理论能讲清楚、公式能追溯、曲线能读懂、交互能即时验证、仿真能复现、工程结果能核对”的 PLL 学习与实验体系。网页负责快速理解，Notebook/仿真包负责深入验证；两者共享实验 ID、参数、数据和来源，但不混淆模型等级。
